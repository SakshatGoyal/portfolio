# Selected Work Cover Page Evaluation

This note records the visual principles used for `cover-iterations.html` after the scope was corrected from a single case-study cover to a full portfolio cover page.

## Design Condition

Each iteration must show the complete project set on entry:

- `01 Palo Alto Networks`
- `02 DocuSign - Global Data Analytics`
- `03 Harvard Business School`
- `04 DocuSign - OneReport`

The first project must be the strongest click target. The first two projects must be visible immediately. The fourth project must be visible or clearly teased so a first-time visitor understands there is a mobile design case study in the collection.

## Reference Principles Applied

### Ekin Tumer
- Fixed index language, compact project list, strong right/side navigation logic.
- Used for: featured-index and split-rail systems.

### J-BM
- Sparse ledger rows, white space, quiet typography, and metadata-first project ordering.
- Used for: ledger-row system.

### Karolis Kosas
- Large editorial statement with project objects underneath.
- Used for: editorial-shelf system.

### Karina Sirqueira
- Image-as-object composition, where each project thumbnail has object presence rather than card decoration.
- Used for: object-grid system.

### Sebastian Hemetsberger
- Severe dark studio composition, large declaration, and compact supporting project wall.
- Used for: dark studio wall.

### Michael Lo
- Board/index language with tiny labels, direct project names, and image material arranged as an archive.
- Used for: board-index system.

## Implementation Rules

- All seven iterations include all four project names in the first viewport.
- Palo Alto Networks is visually dominant in every iteration through larger image area and/or title scale.
- The DocuSign OneReport mobile project is visible on entry in every iteration.
- No ornamental shadows, decorative gradients, or unrelated assets were introduced.
- Each project uses the existing project thumbnail assets from `assets/project-tiles/`.
