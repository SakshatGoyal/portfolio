# 6. How did “Focus” and “Filters” behave once the data became messy?

**Category:** Missing information or evidence  
**Caliber markers:** Craft at zoom, provenance, defensibility

**Question:** How did Focus, Filters, and selectable business lenses handle multi-select, incompatible dimensions, zero or sparse results, hierarchy changes, backtracking, comparison, saved views, and the difference between narrowing a population and changing the metric's denominator? What did users misunderstand in testing?

**Reason for investigation:** The image sequence shows column selection and a Focus sheet, but mostly in a clean happy path. The story claims the same dataset and subsets could be used as lenses, focus targets, and filters, and that the framework “scaled easily” as directors added priorities. That flexibility is exactly where enterprise analytics tools become dangerous: controls that look interchangeable can alter the meaning of a number in materially different ways.

At Staff level, the zoom test includes state logic and semantic clarity, not just a striking hero composition. A public-product leader would worry about learnability and recoverability. An enterprise leader would worry that two executives could create apparently comparable views with different denominators and reach conflicting conclusions.

**Learning objective and decision relevance:** I want the interaction rules, edge cases, error prevention, terminology decisions, and evidence of a design change caused by user confusion. If the designer can show that the controls preserved analytical meaning and that the system explained context, I would see platform craft. If these states were deferred because the work remained a concept, the case should acknowledge that limitation rather than claim easy scalability.

## Answer

There was one rule I treated as inviolable, and it's the most defensible piece of interaction logic in the project: Filter changes the denominator; Focus never does. Filtering to Direct channel recomputes the world — totals, node values, deltas all now describe the Direct population. Focus is the opposite contract: pick CLM from the Focus sheet and every value on screen stays identical; the CLM-touching paths render in color while everything else drops to grey. You can verify this in the artifacts — in the focus sequence, ISV stays 26k, None stays 24k before and after; only the ink changes. The reason for the split is the failure mode this question names: two executives producing "comparable" views with different denominators. Focus exists so the most common exploratory act — where does this unit flow? — is guaranteed semantically inert. The alternative was the industry default: one highlight-style filter that dims and recomputes together, which most BI tools ship. I rejected it because it blurs narrowing and re-basing. Testing later showed that the two-control solution added real learning cost.

The supporting state decisions, quickly. Sparse combinations: zero-valued nodes stay on the canvas — the Net New screen shows "SI: 0" and "Reseller: 0" as labeled nodes with no ribbon. The alternative was collapsing zeros into Other; I kept them because a disappearing column value makes quarter-over-quarter reading treacherous — absence should look like zero, not like a schema change. Column composition: the Columns sheet uses checkboxes plus drag handles, with two hard rules — Total is always the source, Customers is always terminal (grain only degrades leftward-to-rightward). Backtracking: undo/redo are first-class buttons in the bottom bar, deliberately promoted, because exploration only feels safe when any state is two taps from recoverable; a five-control thumb bar (filter, columns, focus, undo, redo) was the price.

What testing surfaced: the grey states confused people. Three of the five directors initially read greyed flows as "removed," i.e., they interpreted Focus as Filter — the exact confusion the model existed to prevent, reproduced at the perception layer. That finding produced a real change: my first design had focus dimming to near-invisibility; I rebuilt it so grey flows remain plainly present, which the final screens show. One director also tapped a QoQ label expecting an explanation of the delta and got nothing — noted, never designed.

Now the accounting of what stayed unsolved, because "the framework scaled easily" deserves qualification. Scaling easily was true for vocabulary — adding a director's lens or values was cheap. It was not demonstrated for state logic. Multi-select Focus across lens groups (CLM and Japan simultaneously): undesigned; the sheet implies single-select. The QoQ semantics under combined focus-plus-filter: genuinely ambiguous — is the delta against the filtered prior quarter or the unfiltered one? — and I never resolved it; those placeholder ±12.87% values conveniently spared me. Saved views, comparison mode, hierarchy changes mid-session, incompatible dimension pairs: all deferred. These were concept-stage prototypes, and the state machine was maybe thirty percent specified. I'd rather claim a strong invariant and a thin state inventory than pretend the edges were done.
