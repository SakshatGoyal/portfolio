    Row anchors and attachment chips require an ease-out animation when entering or exiting the prompt entry field . Currently, they appear and disappear instantly, leaving users unsure whether an action occurred.

    This update applies an ease-out animation, using the same curve as a standard flyout, with a larger distance-to-duration ratio for anchored rows and columns to emphasize the addition of anchored rows to the prompt entry field.

    Related issue: #1086

    The class-based animation will replay each time a tag remounts. Since the attachment list is keyed by array index (key={i}), adding a chip is fine, but removing one from the middle shifts the remaining indexes and restarts their entrance animation. The cleanest fix is to key each attachment by a stable name or id instead of the index.

    Good direction, and the curve choice looks right. cubic-bezier(0, 0, 0.38, 0.9) gives us the decelerating entrance feel we want, so the chip settles into place cleanly.

    The reduced-motion branch is covered too. I have a few notes below, but nothing blocks the direction.

    Exit animation needs one clear chip state value, such as entering, present, or exiting. If the parent removes the node immediately, there is no frame left to animate. That would be a small behavior change with a JavaScript lifecycle, not just a CSS update. I am comfortable with you choosing the timing.

    These same chips also render in user-message.css. If this keyframe stays local, it will likely get copied later and drift. We should consider moving pef-anchor-enter into a shared stage-motion utility once this pattern settles.
